# TASK

이 문서는 Task 수행 계약을 정의한다. Task의 Final Goal과 현재 실행 상태는 `STATUS.md`가 관리한다.

## Scope

- 사용자가 제시한 공용 프로젝트 제작 의도를 평가 기준으로 명시한다.
- 현재 공용 하네스의 워크플로우, 전체 디렉터리 구조, Project/Task 문서의 역할과 내용을 분석한다.
- 필요하면 하네스의 핵심 동작에 관여하는 skill, hook, subagent 운영 규칙을 분석에 포함한다.
- 세 가지 독립 관점(현 구조 친화적 개선, 강한 비판, 현 구조 비의존 신규 설계)으로 대안을 도출한다.
- 세 분석의 공통점, 충돌점, 트레이드오프를 종합하고 실행 가능한 개선 계획을 제안한다.
- 이 Task에서는 분석과 계획까지만 수행하며, 공용 하네스의 실제 구조 변경과 Promotion은 수행하지 않는다.

## Workflow

```text
사용자 의도와 현 하네스 자료 식별
  -> 세 독립 분석 수행
  -> 각 분석 결과를 Task 내부에 기록
  -> 공통점·충돌점·트레이드오프 종합
  -> 양립 불가능한 대안은 선택지로 분리
  -> 단계별 개선 계획 작성
  -> 검증 및 사용자 보고
```

## Outputs

- 세 관점의 독립 분석 기록
- 분석 결과의 종합안과 선택이 필요한 대안 비교
- 우선순위, 의존성, 검증 방법을 포함한 개선 계획
- Task 수행 결과를 정리한 `REPORT.md`

## Completion Criteria

- 세 관점 모두 사용자 의도, 워크플로우, 디렉터리 구조, 문서 체계를 다룬다.
- 각 분석의 우려점과 구체적인 개선안 또는 대안 설계가 기록된다.
- 종합 결과에서 합의 가능한 개선과 상충하는 선택지가 구분된다.
- 상충하는 선택지마다 장점, 단점, 우려점이 제시된다.
- 개선 계획에 우선순위, 선행 조건, 예상 변경 대상, 검증 방법이 포함된다.
- `projectctl task validate`와 관련 프로젝트 검사가 통과한다.
